## 5. 播放失败（最高优先）——双根因定案（已证实），一侧已修、一侧属外部

失败全链（(77) 日志）：2 首歌（ncm_1959667347、ncm_486188245）死在 EdgeOne 取流环；同窗另 7 首全成功；与 (77) 路由退避零交集——「(77) 改动致回归」不成立（判读已定案）。本包按数据通路审计继续追到函数应答层：

**(a) missing 类主因——客户端漏参（已证实，本包已修）**：先审计网页版数据通路：网页版取流原式为 `/song/url/v1?id=&level=&randomCNIP=true&https=true`（folia-major netease.ts），iOS 客户端此前只带 id/level/cookie，漏 randomCNIP。2026-11-24 本机对照实测（Netlify 函数、匿名、level=exhigh，其余条件全同、只动 randomCNIP 一项）：1959667347 不带 → url:null / code:404 / cannotListenReason:1，带上 → 回真实地址；486188245 同样由 missing 变回真实地址（两首各两轮互证）。函数侧启动时已备随机 CN IP（bootstrap 的 generateRandomChineseIP），参数置真才用——这类歌按请求 IP 归属地发流，不带参数即被上游判无权。本包已补 randomCNIP=true 与 https=true，与网页口径对齐。

**(b) 401 类——EdgeOne 默认域名访问保护（已证实根因，属平台侧外部，不假装修好）**：失败那腿 n1 = EdgeOne 直连默认域名（folia-netease-*.edgeone.cool），377ms 回 HTTP 401。函数代码通查无 401 路径（应答恒为 JSON 200＋业务 code）；本机（境外 IP）实测同路径回 200、耗时 4.1s；客户端文件头自 2026-11-14 即有记录「大陆网络直连 *.edgeone.cool 曾回 401 访问保护」。定性：EdgeOne 平台对默认域名的访问保护在边缘层拦截大陆网络请求，函数根本没被执行。此项在本仓库内无从修复——根治需 Miller 在 EdgeOne 控制台关闭该域名的访问保护、或为函数绑定自定义域名（外部操作，未在本包执行）。当前格局下 Netlify 主腿是实际通路，本次 (a) 修好后主腿对这两首歌已能独立成事；备腿 401 的剩余风险是「主腿超时＋备腿被拦」同窗时整次取流仍会失败（概率已随 (a)(c) 大幅下降），如实记于此。

**(c) 客户端韧性（已落）**：①超时收敛——hedge 加总时长 7s 硬顶（哨兵任务到点取消两腿、未归腿记 pending、hedge.fail 带 cap=1）；治的是单腿 URLRequest 6s 只是空闲间隔超时、一腿能跑 12,808ms 把整次取流拖到 13.4s 的旧账。②失败面包屑补全——终败收口行 stream.fail78（带 sess 旗）；stream.fetch 三行会话旗由 cookie= 改 sess=（旧键被日志管线脱敏成 <redacted>、yes/no 根本落不下来，(77) 日志判不出带没带会话——见证缺陷一并修复）。③换腿重试口径交代：hedge 本即双腿并行竞速（先成先用），QueueManager 对瞬时类另有整次重试 1 次（stream.retry，既有）；本包未在客户端再叠一层重试，避免把自动跳歌前的等待拉长——重试层级维持两层、均有日志。
